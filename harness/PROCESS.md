# 1 つの項目の進め方（毎回この順番。飛ばさない）

担当：リリーが作る ／ マツリが合否 ／ カニ係が進み具合 ／ 通治さんが方向と好み。
時刻の締切はない。1 項目できてゲートが全部 ◯ になったら、すぐ【提出】する。4 本の流れ（通し版／不具合／クレジット／手触り）は並行してよい。

## 手順 1　計画（始める）
1. `node harness/scripts/plan.js next` で次の項目を見る（差し戻しが一番先）。
2. `node harness/scripts/plan.js start <ID>`（順番を飛ばすなら `--reason "理由"`）。状態が「作業中」になり、時刻が入る。
3. 出てきた【進捗】文（`harness/out/progress_<ID>.md`）をそのまま #cloe-dot に出す。PLAN の状態表が付いている。
4. PLAN.md のその行の「終わりの条件」と「確かめ方」を読み、足りない情報があれば【進捗】に書いてから作る。

## 手順 2　GPT Pro と相談（手触りの値を決める項目：F05〜F09。ほかの項目で値を決めるときも使う）

## 手順 3　作る
- PLAN.md の行の「中身」だけを作る。ほかの項目に手を出さない（気づいたことは【進捗】に書く）。
- 手触りの値はコードに直書きしない。全部 feel.json（FeelConfig）から読む。
- テスト用フックは TEST_HOOKS.md の名前のまま。
- 作ったらコミットする。ZIP は `dist/<版名>.zip`、版名は `VERSION` に 1 つ。ZIP を GitHub Release か Google Drive に上げ、リンクを `harness/evidence/links.json` の `"zip"` に書いてコミット。

## 手順 4　ゲート
`bash harness/scripts/gate.sh <ID>`。出力の最後が `GATE-RESULT: ALL-PASS` なら手順 6 へ。`FAIL` なら手順 5。

## 手順 5　直すループ（全部 ◯ になるまで）
1. ✕ の行の「くわしく」と `harness/out/`（`pw.log` `suite.log` `feel_*.json` `throws.json`）を読む。
2. 原因を 1 つ決めて直す → コミット → ZIP を作り直す → 上げ直す（版名を上げる）→ links.json を直す → 手順 4。
3. **同じチェックが 3 回続けて ✕**（ゲートの出力に `STOP-AND-REPORT` が出る）なら、原因と必要なものを #cloe-dot でマツリに 1 行で報告する。報告したら別の手で続けてよい。
4. **ゲートの中身（テスト・チェックの条件）をゆるめない。** テストが間違っていると思ったら、直さずに【進捗】でマツリに理由を書く。名前の違いだけは `kani-helpers.js` を直してよい（「変えた値」に書く）。

## 手順 6　動画（その項目で動画が要るときだけ：T02、F10、R01）
- 通し動画：`node harness/scripts/record_playthrough.js`（台本どおりに撮る）→ `harness/evidence/playthrough.webm`。
- 比較動画 3 本：`node harness/scripts/record_compare.js` → `harness/evidence/compare/{mashimashi,futsuu,off}.webm`。3 本とも同じ入力（強 100・40°）。
- 上げて、links.json の `playthrough`／`compare.*` にリンク。CHECKLIST.md に秒数とリリーの ◯ を書く。コミットしてもう一度ゲート。
- 手触りの技を 1 つ入れるたびの「オン／オフの短い動画か GIF」（spec 5-2 F1）は【進捗】に付ける（ゲートでは見ない）。

## 手順 7　【提出】
1. `node harness/scripts/plan.js submit <ID>`。ゲートが全部 ◯・今のコミットと同じ でないと止まる。状態が「提出済」になる。
2. 出てきた `harness/out/submission_<ID>.md` の「（書く。…）」を埋める（変えた値・まだできていないこと）。それ以外は書き換えない。
3. #cloe-dot に出す。形は下（plan.js が作る形と同じ）。SUBMISSION_RULES.md に 1 つでも当たるとマツリが読まずに差し戻す。

```
【提出】カニとばし／<ID> <中身>
項目ID：<ID>
版名：<VERSION>
SHA256：<ZIP の SHA256>
ダウンロード：<GitHub か Drive のリンク>
コミット：<40 桁>
動画：<リンク。不要なら「なし（この項目は動画不要）」>
変えた値：<FEEL_DECISIONS.md のこの版の表、名前を直したところ。無ければ「なし」>
満たした条件：<M・#>
まだできていないこと：<無ければ「なし」>
次の担当：マツリ（確認）
ゲート出力：
（gate.sh の出力を全部、```で囲んで）
PLAN 状態：
（=== PLAN STATUS === から === END PLAN STATUS === まで）
```
4. マツリかカニ係が `plan.js set <ID> 合格|差し戻し --by マツリ` を付ける。差し戻しは次に一番先に直す（手順 1 に戻る）。

## 【進捗】（作業の途中で出すとき。いつでもよい）
`node harness/scripts/plan.js status` の出力（PLAN STATUS の塊）を必ず付ける。形：
```
【進捗】カニとばし／<ID>
やったこと：…
次にやること：…
困っていること：…（無ければ「なし」）
（PLAN STATUS の塊）
```
