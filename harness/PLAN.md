## 使い方（3 行だけ）
1. 始めるとき：`node harness/scripts/plan.js next` → 出た項目を `node harness/scripts/plan.js start <ID>` → 出た【進捗】文を #cloe-dot に出す。
2. 終わるとき：`bash harness/scripts/gate.sh <ID>` → 全部 ◯ なら `node harness/scripts/plan.js submit <ID>` → 出た【提出】文（`harness/out/submission_<ID>.md`）にリンクを足して出す。
3. ✕ があれば直して 2 をやり直す（PROCESS.md の「直すループ」）。時刻の締切はない。できたらすぐ出す。

## 決まり（表の読み方）
- **上から順番**：同じ「流れ」の中は上から順に取る。依存がそろっている前の項目を飛ばすときは「順番を飛ばした理由」を書く（`plan.js start <ID> --reason "…"`）。理由なしで飛ばすとゲートが ✕ にする。
- **流れは同時に進めてよい**：通し版／不具合／クレジット／手触り の 4 本は並行してよい。公開 は最後。
- **通し版が先**：手触りの「値の仕上げ」（F05 から下）は、T02（通し録画と 3 回続けて遊べる）と B01・B03（未発射 0・床停止 0）が提出済になってから。手触りの「仕組み」（F01〜F04）は通し版と並行して作る（spec 12-2 の順番）。
- **状態は 5 つだけ**：未着手 → 作業中 → 提出済 →（マツリ・カニ係が）合格 ／ 差し戻し。合格と差し戻しはマツリかカニ係だけが付ける。差し戻しは次に一番先に直す。
- 「確かめ方」の `G-…` はゲート（`gate.sh`）のチェックの名前。中身は README.md の「チェック一覧」。
- 動画とZIPは **GitHub（raw か Release）か Google Drive のリンク**で出す。Slack の添付はこちらで取れないので不可。
